# 嗶哩漫畫

## 0.1.13 簡介與多語言顯示

嗶哩漫畫（bilimanga.net）收錄日本、韓國、港台、歐美與大陸漫畫，涵蓋奇幻冒險、校園戀愛及懸疑驚悚等題材。

零參 `source_info` 固定使用以上基準簡介；`metadata.localization` 僅新增 `source.description` 的繁中、簡中與英文文案，供支援的宿主顯示。

`net.bilimanga.koma` 对应 `https://www.bilimanga.net` 的「嗶哩漫畫」。参考 Keiyoushi
`16cde44564d45c3fa9c14371b4d9152606a9821d` 的 `zh/bilimanga` 和固定 Core，扩展
1.6.15，来源语言 `zh`。Mihon 网络参考固定到 `70c73c728b6350dd9f1447420e9cef54e8403b41`。

| 行为 | 上游与 Koma 适配 |
| --- | --- |
| 浏览与分页 | `BiliManga.getPopularManga`、`getLatestUpdates`、`mangaPageParse`。`get_manga_list` 的 `list` 沿用 11 个热门榜、最新和 10 个分类字段，从 `args.page.cursor` 读页数。榜单按 50 项，分类按真实当前页与尾页。 |
| 作品地址与关键词搜索 | 同站的作品地址仍直接解析详情。关键词依据 [Keiyoushi 1aba299d](https://github.com/keiyoushi/extensions-source/commit/1aba299dd03549a98d6f4461f6022d1e9adf04c0) 的 `searchDocument` 直接 GET `/search/{关键词}_{页}.html`。收到图片验证码表单时沿用宿主网页验证，支持 HTTP 200 文档因果标识的宿主直接打开本次搜索的验证码页。用户输入验证码后，支持网页就绪声明的宿主看到搜索结果或直接跳转的作品详情，自动关闭并沿原查询重试。旧宿主仍可手动完成。区分普通结果页和精确命中跳转的详情。 |
| 目录 | `fetchMangaUpdate` 对应 `chapters`。按原分卷、锚点、标题和顺序返回。不按网页标题的总话数补造目录。保留原生成的 `#prev`、`#next` 章节身份。 |
| 正文 | `ChapterInterceptor`、`getPageList` 对应 `pages`。片段仅是本地跳转指示，第一跳不增加 `night=1`。次跳由网页给出的同书导航解析为 `_2.html`。缺失或非同书导航明确失败，不猜章节号。页面位置、原始图片地址、重复页与附页均保留。已实测的桌面浏览提示保留具体原因。书架续读时宿主可能传 `source://` 内部定位串，正文请求只把它当无 URL，不参与作品路由校验；作品身份仍由 `mangaId` 约束。 |
| 封面与图片 | `KeiSource` 的 `Fetch.IMAGE` 对应 `write_cover` 和 `image_request`。同站封面按路径作品归属。正文沿用网页的原地址，在页表和取图时共用校验，仅接受已确认的两个 HTTPS 图片域。兼容旧的 `/img/<内容摘要>.<格式>` 与站点现行的 `/<分桶>/<作品>/<章节>/<图片编号>.<格式>`，保留 AVIF 和 JPEG。现行路径校验作品，生成页表时也核对实际打开的章节；旧 `#prev`、`#next` 页身份仍保留原锚点，取图时按已核对的页表 URL 请求。公开图片头不携游客、登录或夜间 Cookie。 官网 `c.motiezw.com` 的作品封面先校验路径作品归属，再使用官网同域的 `/files/cartoon/image/` 对应地址，保留尺寸后缀与时间戳。浏览、详情及已保存 CDN 地址共用此转换，正文仍沿用实际图片 CDN。 |
| 设置 | `POPULAR_MANGA_DISPLAY`、`RATE_LIMIT`、`DESCRIPTION`。热门默认周点击榜。请求速率默认 10/10，由 Koma 宿主共享限速并在进程重启后应用新设置。简介默认显示公告、别名、小说链接。速率在宿主读取时校验，源设置仍是文本字段。兼容宿主另提供上游的 `SOLVE_CAPTCHA`，默认关闭。 |

支持 `source_http_response_metadata_v1` 的宿主可在同一搜索请求里返回最终地址并保留原验证码请求标识。精确命中跳转到作品详情时，从同源的最终作品地址取 ID，旧宿主继续读取公开目录链接。

具备 `source_interaction_resume_v1` 的前台源内搜索会把站方验证发生时的处理标记随原挑战返回。验证交互完成后，宿主在原查询与原页重试中带回标记。书源保留完全相同的 HTTP 请求，依当前网站结果判断，已完成的这次交互不重复提交续接标记。

浏览与阅读继续使用宿主书源限速。关键词搜索复用现有的同源网页会话，不再请求旧
`search_guard` 换票端点。网站当前标示验证通过后 30 分钟内可继续搜索，到期会再次提示。
启用「自动输入搜索验证码」后，源内按照上游 `SearchCaptcha.kt` 的数字字模识别，
连同表单隐藏字段提交，最多尝试三次。图片解码与识别均在 WASM 内执行；宿主只提供
`source_http_bytes_v1` 二进制响应与 `source_http_cookie_session_v1` 原生 HTTP 会话，
不需要验证码专用接口。两项能力都存在时才展示开关；缺少能力的旧宿主保留原有手动路径，
不会误发新请求。自动识别未成功时仍可进入已有网页验证。与上游 Android Bitmap 解码的
适配差异是源内有界 PNG 解码（非交错 8 位、最大 256×128，图片输入最多 64 KiB）。
书源包声明最低 Koma 版本仍为 1.4.1。每部作品的目录更新时间映射到该作的章节日期，按 UTC+08:00
午夜输出。缺失或无效日期省略字段。相关作品保留 Komikku 专用差异。

原网页与 WASM 已对照六个榜单／分类页面、173 部不同列表作品、50 部详情与目录、9754 个
目录位置、16 个正常章节的 413 个图片位置，以及真实游客搜索的结果页和详情跳转。素材出处见
[ASSET_SOURCES.md](ASSET_SOURCES.md)。设备验收和公开登记单独记录。

## 0.1.8 搜寻验证码

2026-11-19 在 237 的 Koma 1.5.4（23）通过本地导入验证。源内搜索「芙莉蓮」弹出同站网页，在网页搜索并完成图片验证码后点击「完成并重试」，原查询返回作品和封面；继续搜「魔法」直接返回多条结果。《葬送的芙莉蓮》详情与 147 章目录可打开，第 127 话 P1 的图片 CDN 在收到响应头后传输超时。已验证范围是搜索、详情和目录。旧宿主仅按已有能力核对，本轮未实机运行。

## 0.1.12 自动输入搜寻验证码

2026-11-21 在 237 覆盖安装包含两项新 HTTP 能力的 Koma 1.5.6（25）候选，
由普通文件入口导入 0.1.12，回读 WASM 与本机最终构建一致。
开启自动输入后，原生搜索「芙莉蓮」实际依次完成 GET 搜索、GET 图片、POST 表单、
302 跳转及 200 详情，返回《葬送的芙莉蓮》与封面，没有人工输入或网页弹窗。
重新安装 App 后再次从空的原生 HTTP 会话完成同一流程；同词重搜及换词「魔法」
均只发送原搜索 GET（保留正常跳转），没有重新取图片或提交验证码。
另核对了详情及 147 章目录。此轮不作为正文图片、下载或识别成功率的全量验收。
最终 WASM 在未声明新能力时的回放保持普通结果与手动验证码路径；未在旧版 App
真机安装本候选。源码与本地候选的状态以 Koma 当前工作单为准。

作品评论读取原站详情中公开展示的「書評感想」。网站完整书评列表要求登录，访客只看到详情公开的书评，隐藏剧透维持原样。
